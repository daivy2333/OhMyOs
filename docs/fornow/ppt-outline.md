## Slide 4：为什么做异步驱动

- 两难：纯轮询，空闲时 CPU 空转；纯中断，吞吐一上来就是中断风暴
- 方案：中断只负责唤醒，后台 copier 批量搬运（NAPI 思路）——空闲全链路睡眠，忙时批处理压中断次数；队列有界、背压可见、可恢复
- 版面：左轮询 / 右中断各一句痛点，中间 IRQ → waker → copier 箭头示意

## Slide 5：开发范式——统一骨架与四条契约（核心页）

- 触发链四段：ISR 收中断 → 读寄存器识别原因 → 唤醒 waker → 调度异步任务
- 四条契约：
  1. ISR 不搬数据，只做原因确认、清中断、唤醒
  2. waker 注册后立即重查硬件状态，防丢唤醒
  3. 每轮工作量有上限，积压显式可见
  4. 返回等待前先释放锁再唤醒，防死锁
- 版面：上半四段链条图，下半四张契约卡片

## Slide 6：范式对照——串口 vs 网卡

- 同构部分（范式覆盖的范围）：四段骨架同一套写法；同一个 `embassy_sync::AtomicWaker`；同一组 OS 抽象 trait（`OsRuntime`/`OsWakerSet`），驱动不依赖具体任务实现
- 差异部分（范式不管的范围）：数据结构层——串口是字节流 + 双 SPSC 环形缓冲；网卡是整包 + 描述符固定槽位 + 代际序号
- 不抽象的理由：completion 语义、背压表达、故障分类在两个设备上完全不同，强抽 trait 会退化
- 结论句：骨架照范式写，数据层按设备设计
- 版面：左右对照表（行 = 四段骨架 + 数据层 + OS 抽象）

## Slide 7：范式落地——网卡五层

- 五层数据流：ISR → 队列 owner（唯一后台任务，收发预算制推进）→ 栈 runner（推进 smoltcp 收发、维护、定时器）→ 就绪桥（单槽 waker 展开成多等待者，接 poll/select）→ socket
- 发送记录：每次发送带代际号 + 序号；提交 = 完成 = 回收三处计数闭合后缓冲区才复用；迟到的完成通知不跨代生效
- 恢复语义：等待者取消 / 提交前撤销 / 设备持有三段区分；复位必须确认设备清零后才重建队列
- 故障注入结果：无重复释放、永久挂起、静默丢包
- 版面：纵向五层数据流图，右侧挂"发送记录""恢复"两个小框

## Slide 8：扩展——多核绑核与跨核唤醒

- 背景一句：目标板 K3 有 8 × X100 + 8 × A100 共 16 核，后台角色必须固定绑核
- 绑核规则：角色 i → 可调度集合第 (anchor + i) 个，入队前完成；网卡 owner/runner、串口 RX/TX copier 各占一核
- 唤醒：本地优先；必须跨核时恰好一次 IPI，避免唤醒风暴
- 观测：串口 152 字节、网卡 V5 两组快照命令，直接读出"谁跑在哪个核"
- 结果一句：SMP=16 六组场景全过，IPI 发送 = 接收
- 版面：16 核方块图，标注四个角色的落点

## Slide 9：两驱动共存与范式推广

- 共存证据：网卡开发与测试全程，串口一直承担控制台 I/O——SMP=16 运行记录本身就是经串口打印的；两个驱动在同一内核共存工作
- 推广路径：新异步驱动照四段骨架写、守四条契约，数据结构层按设备设计；骨架层抽框架待第二个非网卡设备稳定后评估，避免把演进中的常量写死
- 版面：一条共存事实 + "四段骨架 → 更多设备"扩展示意
